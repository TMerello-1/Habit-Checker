# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Habit Checker: a progressive web app that reminds users of scheduled habits and rewards them for keeping streaks. Plain HTML/CSS/JS with native ES modules. There is no build step, no bundler and no runtime dependencies; files are served as-is.

## Commands

```sh
npm start                                  # serve on http://localhost:8080 (python3 -m http.server)
npm test                                   # run all tests (node --test auto-discovers tests/*.test.js)
node --test tests/habits.test.js           # run one test file
node --test --test-name-pattern="streak"   # run tests whose name matches
```

`node tools/build-preview.mjs > preview.html` bundles everything into one self-contained HTML fragment, which is published as the hosted phone preview (a claude.ai Artifact, https://claude.ai/artifact/2eL4pDTn9FzPCuGHEkdByx). Service workers and notifications don't work there, and `confirm()`/`alert()` are blocked, so keep UI confirmations in-page.

Requires Node 22+ (the built-in `node:test` runner). Don't pass a directory to `node --test` because Node 22 treats it as a module path and fails. The app must be served over http(s), not opened via `file://`, or the service worker and module imports won't load.

## Architecture

- `src/habits.js` holds the pure domain logic: scheduling (`isScheduled`), streaks and rewards. It has no DOM or storage access, which is what lets it be unit-tested under Node. New logic belongs here when it can be pure.
- `src/app.js` is the only file that touches the DOM. Every mutation goes through `commit()`, which saves state and re-renders the whole view. There is no framework and no partial diffing. The page puts Today first; habits are added and edited in a bottom sheet (`#habit-dialog`) opened by the floating ＋ button, and badges live in the Progress sheet opened from the level in the header. Until noon, yesterday's missed habits can still be checked off (`missedYesterday()`).
- `src/store.js` keeps the entire app state as one JSON blob in `localStorage` under `habit-checker:v1`: `{ version, habits, completions, notified }`. If the shape changes, bump `version` and migrate in `load()`. Per-device view preferences (open sections, dismissed banners, "Ask before checking off") live apart from it under `habit-checker:ui` (`loadPrefs()`/`savePrefs()`).
- `src/reminders.js`: `dueReminders()` is pure and tested. `notify()` shows notifications through the service worker registration. `state.notified[habitId] = "YYYY-MM-DD"` stops a reminder from firing twice in a day. `setBadge()` puts the count of today's open habits (`openToday()`) on the app icon on every render; the Badging API only exists on desktop (Windows/macOS), and on Android the icon shows a dot only while a notification is up, so checking a habit off closes its reminder via `dismissReminder()`.
- `src/install.js` picks the "Install app" help text per browser (pure, tested). `app.js` uses the browser's `beforeinstallprompt` dialog when Chromium offers one and shows these menu steps otherwise; the button hides once the app runs standalone. Installability depends on the PNG icons in `manifest.webmanifest` (rendered from `icons/icon.svg`).
- `src/i18n.js` holds all UI text in English and German. `t(key, vars)` looks strings up in the current language, which `app.js` picks from `navigator.languages` (English fallback); `index.html` keeps the English text and marks elements with `data-i18n`, `data-i18n-placeholder`, `data-i18n-aria-label` or `data-i18n-day` so `app.js` swaps in translations at startup. New user-facing text goes in both languages (a test checks they match). The Android app's text lives in `res/values/strings.xml` and `res/values-de/strings.xml`.
- `src/changelog.js` is the "What's new" list shown in the ⋮ menu's Help dialog (English and German per entry, pure, tested). When a user-visible change ships, add an entry at the top with the next `v`; `notable: true` also shows a one-time "New: …" banner to existing users (the device remembers the last version seen under `habit-checker:seen`).
- `src/transfer.js` exports and validates the state as copied text (pure, tested), for the "Move your data" section that carries habits between the PWA and the Android app.
- Friends: `friends-server/` is a Cloudflare Worker with a D1 (SQLite) database (`schema.sql`), deployed by `.github/workflows/deploy-friends-server.yml`; its tests run the real SQL on `node:sqlite` through `tests/fake-d1.js`. Profiles are anonymous: a name from `src/names.js` (stored as list positions plus a number, so each viewer reads it in their own language; only ever append to those lists) and a recovery code from `src/codes.js` that doubles as the bearer token (the server keeps only its hash). Friends link through single-use invite codes and see each other's name, level and best streak (`sharedStats()` in `habits.js`, which skips private habits). Habits reach the server only as an encrypted backup: while signed in, `app.js` uploads the habits, history and nicknames (`PUT /me/backup`) after changes, encrypted by `src/backup.js` with a key derived from the recovery code, and signing in with the code offers it back (`checkBackup()`); `friends.backup` stays false until that choice is made, so a fresh sign-in never overwrites the backup. Devices on the same profile sync through that backup (`syncNow()`: fetch, `mergeStates()` from `src/sync.js`, store with `base` = the fetched `updatedAt`, retry on 409). `commit()` stamps every change in `state.sync` (`stamp()`: per-habit edit and deletion times, per habit-day check-in times), and the newer stamp wins per habit and per day; to change state without stamping (taking over another device's copy) use `adopt()`. `src/friends.js` talks to the server and keeps the code, private nicknames and a cached friends list under `habit-checker:friends`, apart from the habit state. The Friends section stays hidden while `FRIENDS_SERVER` in `src/config.js` is empty. `app.js` renders it with `renderFriends()`, not `render()`, so a re-render doesn't wipe a code or nickname being typed. Invite links are `…#invite=CODE`. The ⋮ menu's "Send feedback" posts to the same server (`POST /feedback`, no profile needed; when signed in, the bearer code makes the server record the sender in `feedback_senders` so admins see their name, otherwise the inbox shows "No profile"); profiles named in `ADMINS` in `friends-server/wrangler.toml` get `admin: true` from `GET /me`, which shows a "Feedback inbox" menu entry to read and clear it. An admin device with push reminders on registers its push endpoint (`PUT /admin/device`), and each new feedback is pushed to it through the push server: the friends worker calls `https://internal/notify` on the push worker over the `PUSH` service binding, a host the public internet can't reach. Admin pushes are throttled to one per 5 minutes (`admin_push` table), with "(+N)" for the rest. Admins can reply to and react to feedback; senders stay anonymous because `POST /feedback` returns a random token that the sender's device keeps (threads under `habit-checker:feedback`, logic in `src/feedback.js`) and uses as `X-Feedback-Token` on `/threads/<id>` to read and answer; replies are pushed to the sender's endpoint when it has one (`#feedback` opens their threads). The inbox is a filterable table (`filterFeedback()`). The Android app has no push, so `FeedbackJob.java` polls every 15 minutes: `GET /feedback` while an admin profile is signed in, and `/threads/<id>` for the sender's own threads (the bridge passes it `habit-checker:friends` and `habit-checker:feedback` saves).
- `android/` is a Java Android app (no dependencies) that loads the GitHub Pages site in a WebView and adds the user-agent token `HabitCheckerAndroid`, which `app.js` checks. A script injected after page load wraps `localStorage.setItem` and passes each save of `habit-checker:v1` to the app, where `Habits.java` re-implements `isScheduled`/open-today for the home screen widget and native reminders (AlarmManager, so they fire while closed). Keep `Habits.java` in step with `src/habits.js` and the state shape. CI (`.github/workflows/android.yml`) builds the APK and publishes it as the `android-latest` release, signed with the `ANDROID_KEYSTORE` secret so it installs over the old app; `Updater.java` offers that release in-app when its "build N" title is newer than the installed versionCode; the Android SDK can't be downloaded in Claude's cloud sandbox, so CI is the only build check.
- `sw.js` is a cache-first service worker for offline use, and it also handles notification clicks.

### Key invariants

- **Dates are local calendar keys** (`"YYYY-MM-DD"`, built by `dateKey()` in `src/dates.js`), never UTC ISO strings. `completions[habitId]` is an array of these keys.
- **Streaks count only scheduled days.** Unscheduled weekdays are skipped and don't break a streak. Today being scheduled but not yet done also doesn't break it. Days before `habit.createdAt` never count.
- **Private habits (`habit.private`) never show their name outside the app**: the web lists put them in a collapsed "🔒 Private" group, and reminders (`reminderTitle()`, `Reminders.java`) and the widget use a generic line instead.
- **Pile habits (`habit.pile`: `"day"`, `"week"` or `"month"`)** let each planned day add a round and each tap take one off; a day appears once in `completions[habitId]` per round. Switching the pile on (or to another period) in `editHabit()` sets `pileSince` to that day: the pile and its streak only count from then, and day badges from before are kept. The pile (`pileCount()`) restarts every period (weeks start Monday) and the streak counts periods that ended with the pile cleared, so badges are in weeks or months and friends see them as days (×7, ×30). They're open on any day the pile is above 0 and reminded on planned days plus the period's last day (`remindOn()`, shared with the push server, mirrored in `Habits.java`).
- **Rewards are derived, never stored.** `rewards()` recomputes points, level and badges from the completion history every time, so un-checking a habit takes its points back. Scoring is 10 pts per check-in plus 50 pts per streak-milestone badge (`STREAK_MILESTONES`), with a new level every 250 pts.

### Reminders and the push server

Reminders come from two places. While the app is open, `app.js` polls `dueReminders()` every 30s. When `PUSH_SERVER` in `src/config.js` is set, `src/push.js` subscribes the device for Web Push and syncs a copy of the habits, the timezone and each habit's latest check-in date to the server after every `commit()`; from then on the server sends the reminders (also while the app is closed) and the in-page polling stands down. With `PUSH_SERVER` empty, push is skipped entirely.

`server/` is the push server, a Cloudflare Worker (KV namespace `SUBS`, cron every minute). `server/src/webpush.js` implements VAPID and RFC 8291 encryption with WebCrypto only (its test checks the RFC example byte for byte). `server/src/schedule.js` works out the user's local date and time from their IANA timezone and reuses `isScheduled()` from `src/habits.js`, so keep that file free of browser APIs. Run it locally with `npx wrangler dev --test-scheduled` in `server/` (needs a `.dev.vars` with `VAPID_JWK`). `.github/workflows/deploy-push-server.yml` deploys it when `server/` changes on main; it needs only the `CLOUDFLARE_API_TOKEN` repo secret and creates the KV namespace and VAPID keys itself.

## When changing files

- Adding, renaming or removing any shipped file means updating the `ASSETS` list in `sw.js`.
- Any change to a shipped file requires bumping `CACHE` in `sw.js`. The worker is cache-first, so without a bump installed users keep the old version.
